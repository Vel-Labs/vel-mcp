# Vision
- The glasses/vision layer should support non-coding use cases including general image understanding, OCR, and PDF reading, not just programmatic GUI automation. Confidence: 0.75
- Maximize the glasses MCP to leverage as much vision model capability as possible — flesh out use case lanes (image understanding, OCR/PDF, video analysis, design feedback loops) at the front door so the MCP is robust for diverse consumers. Confidence: 0.65
- Split image and video into separate lanes within Glasses: image lane handles single-artifact VLM/OCR/grounding, video lane uses a frame-index-first pipeline (metadata extraction → frame sampling → scene segmentation → keyframe VLM → temporal VLM → event index → summary). They share the same MCP interface and provider registry but differ in model selection, caching, sampling, and evaluation metrics. Confidence: 0.75
- Use Qwen3-VL-8B-Thinking-8bit (MLX) as the default general VLM for Apple Silicon, with Qwen3-VL-4B-Instruct-5bit as the fast/fallback profile and Qwen2.5-VL-7B-Instruct-4bit as the stable compatibility baseline. InternVL3-8B-MLX-4bit is a viable second-opinion model for A/B evaluation. Confidence: 0.70
- LocateAnything-3B is a grounding-only specialist, not a general VLM — it returns box/point tokens even for description prompts. Use it exclusively for locate, GUI grounding, and OCR text localization. Confidence: 0.80
- Providers should declare explicit capabilities (e.g., image_qa, screenshot_reading, grounding, gui_localization, video_frame_reasoning) so the router can select models by role rather than hardcoding model IDs in tool handlers. Confidence: 0.65
